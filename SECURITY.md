# Security policy / 보안 정책

## Reporting a vulnerability

Do not post sensitive vulnerability details, exploit instructions, personal note contents, credentials, or confidential company information in public issues or discussions.

**Private reporting setup is pending.** GitHub Private Vulnerability Reporting was disabled when checked on 2026-11-26, and no alternative private security contact has been verified. This policy does not establish an email reporting address.

Check the repository's [Security advisories page](https://github.com/funk80/Butim/security/advisories). If **Report a vulnerability** is available, use that private form. Otherwise, open a public issue asking only for a private security contact, without naming the affected component or including reproduction steps, attachments, or vulnerability details. Wait for a private channel to be confirmed before sending the report.

Once a private channel is available, include the affected Butim version, Windows version, a concise impact description, and reproduction steps using synthetic data. English and Korean reports are welcome.

## Supported versions and updates

No fixed security-support period or version-by-version support guarantee is published. Availability of a release does not imply that it is free of vulnerabilities or guaranteed to receive security updates. Check [GitHub Releases](https://github.com/funk80/Butim/releases) for the latest published version and its release notes; do not assume older versions receive backported fixes.

When security fixes are released, obtain the updated installer from GitHub Releases and follow the release instructions. This policy does not promise a response time, a remediation deadline, or a patch for every report. Any support scope or security guidance announced for a particular release should be stated in its release notes or an advisory.

## 한국어 안내

민감한 취약점 세부 정보, 공격 방법, 개인 메모, 인증 정보, 사내 기밀 자료를 공개 Issue나 토론에 작성하지 마세요.

**비공개 신고 채널은 설정이 필요합니다.** 2026-11-26 확인 시 GitHub Private Vulnerability Reporting이 꺼져 있었으며, 대체 비공개 보안 연락처도 확인되지 않았습니다. 이 정책은 이메일 신고 주소를 지정하지 않습니다.

[Security advisories](https://github.com/funk80/Butim/security/advisories)에서 **Report a vulnerability**가 보이면 비공개 양식을 사용하세요. 그렇지 않으면 공개 Issue에는 비공개 보안 연락처를 요청하는 문장만 남기고, 영향받는 구성요소·재현 절차·첨부파일·취약점 세부 내용은 쓰지 마세요. 비공개 채널이 확인된 뒤 신고 내용을 전달하세요.

비공개 신고 시 Butim 버전, Windows 버전, 영향 설명, 가상 데이터로 작성한 재현 절차를 포함하면 도움이 됩니다. 한국어와 영어 모두 가능합니다.

고정된 보안 지원 기간이나 버전별 지원 보장은 공표하지 않습니다. 릴리스가 게시되어 있다는 사실은 취약점이 없거나 보안 업데이트가 보장된다는 의미가 아닙니다. [GitHub Releases](https://github.com/funk80/Butim/releases)에서 최신 게시 버전과 변경 내용을 확인하고, 이전 버전에 보안 수정이 소급 제공된다고 가정하지 마세요.

보안 수정 버전이 배포되면 GitHub Releases에서 설치 파일을 받아 해당 안내에 따라 업데이트하세요. 응답 시간, 수정 기한, 모든 신고에 대한 패치 제공을 약속하지 않습니다. 개별 버전의 지원 범위나 보안 안내는 해당 릴리스 설명 또는 보안 권고에서 확인합니다.
